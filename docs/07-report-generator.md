# Report Generator

> Code Archaeologist · docs/07-report-generator.md

---

## 1. Principles

- **Deterministic:** same `EvidenceDocument` always produces the same report.
- **No AI tokens:** every sentence is generated from templates with evidence values substituted.
- **Traceable:** every factual claim references an observation ID.
- **Honest:** inferences are labelled as inferences; unknowns are explicit.
- **Audit-ready:** raw tool JSON is preserved alongside the report.

---

## 2. Output Files

| File | Format | Content |
|---|---|---|
| `report/report.md` | Markdown | Human-readable, downloadable |
| `report/report.html` | HTML | Self-contained (inline CSS), downloadable and renderable in browser |
| `report/report.json` | JSON | The full `EvidenceDocument` — same as `evidence.json` |

---

## 3. Report Structure

### 3.1 Section Map

```
1. Identification
2. Analysis Summary (tool coverage table)
3. Observed Findings
   3.1  Binary / Source identification
   3.2  Imports (binary) or File inventory (source)
   3.3  Dependencies
   3.4  Scanner Findings (Semgrep / Trivy / Ghidra functions)
4. Justified Inferences
5. Dependencies & Risks
6. Unknowns / Not Determined
7. Preservation Recommendations
8. Limitations
9. Appendix: Evidence Index
```

---

### 3.2 Section Templates

#### Section 1 — Identification

```md
## Identification

| Field       | Value                                      |
|-------------|--------------------------------------------|
| Analysis ID | `{analysisId}`                             |
| Origin      | {origin}                                   |
| Input       | {input.name}                               |
| SHA-256     | `{input.sha256 ?? "N/A (repository)"}`     |
| Git Commit  | `{input.commit ?? "N/A (file upload)"}`    |
| Analysed At | {generatedAt}                              |
```

#### Section 2 — Analysis Summary

```md
## Analysis Summary

| Tool     | Status    | Version | Data Date | Coverage Notes    |
|----------|-----------|---------|-----------|-------------------|
| {name}   | {status}  | {ver}   | {date}    | {warning ?? "—"}  |
```

#### Section 3 — Observed Findings

Each observation produces one entry:

```md
### [{obs.id}] {obs.summary}

- **Kind:** {obs.kind}
- **Source:** {obs.source.tool} | {obs.source.path ?? "—"} line {obs.source.line ?? "—"} | addr {obs.source.address ?? "—"}
- **Tags:** {obs.tags.join(", ")}
> **Label: Observed**

{obs.detail ?? ""}
```

#### Section 4 — Justified Inferences

```md
### [{inf.id}] {inf.summary}

> **Label: Inferred** | Confidence: {inf.confidence}

**Explanation:** {inf.explanation}

**Supporting evidence:** {inf.evidenceIds.join(", ")}
```

#### Section 5 — Dependencies & Risks

All observations of `kind: "dependency"` are grouped here:

```md
### {pkgName}@{version}

- **Advisory:** {ruleId}
- **Summary:** {summary}
- **Severity tag:** {tags}
- **Label: Finding for review** — this tool result requires manual confirmation.
  See: {source.tool} output reference [{obs.id}]
```

#### Section 6 — Unknowns

```md
## Not Determined

The following aspects could not be established from the available evidence:

{unknowns.map(u => `- ${u}`).join("\n")}
```

Example unknowns generated by the pipeline:
- "Original source language cannot be confirmed from binary alone."
- "Dependency `X` version could not be confirmed — manifest not found."
- "No entry-point function identified."

#### Section 7 — Preservation Recommendations

Generated from observations and inferences using a rule table:

| Trigger | Recommendation |
|---|---|
| Network imports observed | "Preserve network configuration and protocol documentation alongside the binary." |
| Registry imports observed | "Document registry keys referenced or modified by this application." |
| Dependency CVEs found | "Review and patch {N} declared dependencies with known advisories before continued use." |
| No manifest found | "Recover or reconstruct the dependency manifest for long-term preservation." |
| High-entropy strings | "Review redacted strings in the raw evidence file for potential credential material." |

#### Section 8 — Limitations

Always present. Template:

```md
## Limitations

- Static analysis only. No code was executed during this analysis.
- Ghidra pseudocode is a decompiler approximation and does not represent original source code.
- Semgrep rule coverage is limited to the rulesets active at scan time.
- Trivy vulnerability data reflects the database version dated {dataDate}.
- A finding from a scanner does not confirm a vulnerability is exploitable.
- Strings and imports indicate capability, not confirmed use.
- This report was generated automatically and requires human review for any security or compliance decision.
```

---

## 4. HTML Conversion

The Markdown is converted to a self-contained HTML file using:

1. A Markdown-to-HTML conversion (using `marked` or a simple template).
2. Observation-kind labels rendered as styled badges:
   - `Observed` — blue badge
   - `Inferred` — amber badge
   - `Not Determined` — grey badge
   - `Finding for review` — red badge
3. All CSS is inlined; no external resources.
4. A table of contents generated from section headings.

---

## 5. Evidence Index (Appendix)

A table listing every observation and inference ID with a one-line summary:

```md
## Appendix: Evidence Index

| ID      | Kind       | Summary                          | Tool     |
|---------|------------|----------------------------------|----------|
| obs-001 | import     | KERNEL32.dll → CreateFileW       | ghidra   |
| obs-002 | string     | Software\Microsoft\Windows       | ghidra   |
| inf-001 | inference  | Binary interacts with filesystem | —        |
```

---

## 6. No-Results Handling

If no observations were produced by any tool:

- Report includes only Identification, Analysis Summary, Unknowns ("No evidence was collected"), and Limitations.
- This path only triggers if the job reaches `reporting` with zero observations (both tools partial).
- A top-level warning banner is added: "Analysis produced no observations. Review tool warnings."

---

## 7. Generator Module Interface

```ts
// api/src/report/generator.ts

export async function generateReport(
  evidence: EvidenceDocument,
  outputDir: string
): Promise<{ markdown: string; html: string }>;
```

Input: validated `EvidenceDocument`.  
Output: writes three files to `outputDir` and returns the Markdown and HTML strings.

No external network calls. No AI tokens. No randomness — same input, same output.
